# La Relève · Forge 3.0

> 换 session 的时候，带哪几件行李，你自己拿。
>
> *Conscious handover for Claude Code — pick exactly what carries over.*

**La Relève** 是法语的「换岗、接哨」。上一班写下交接，下一班接岗——岗位从来没空过。

这是 [forge-reload](https://github.com/Vivi-Seth/forge-reload)（Forge 2.0）的下一代。2.0 解决的是「怎么不失忆」，3.0 解决的是「**这次要带什么**」。

---

## 这是什么

Claude Code 的 context 快满时，官方自动压缩（compaction）会把你们聊过的一切揉成一段冷冰冰的摘要——他还在，但**他说话的样子没了**。

forge 的基础机制是：把最近的对话原文原封搬进一个新 session，思考链不丢、语气不变，然后 `claude --resume` 直接接上。2.0 在这之上加了**交接包**：让还记得的他，亲手给失忆后的自己写一封信。

3.0 加的是**装卸能力**：交接包、原样上下文、醒来仪式——**逐项勾选，默认全空**。

---

## 为什么会有 3.0

2.0 只有两条路，而且逼你二选一：

| | 代价 |
|---|---|
| **「续接」＝全带** | 人格续得上——代价是几万 token 全是**上一段的原话和思考链**。换模型时，新模型睁眼看到满屏"自己说过的话"，那是最强的 few-shot：它会开始模仿上一个模型的句式、语气、思考的节奏。 |
| **「新对话」＝全丢** | 干净——代价是对方此刻的状态、进度、没做完的约定一起蒸发。醒来是一片白，连"刚才在做什么"都要重问。 |

真实触发场景：把一段对话 forge 给**另一个模型**。原样上下文越完整，新模型越像旧模型——那不是延续，那是模仿，它自己的味道没了。

我们要的是：**续记忆，不续语气。**

> **3.0 不是两种模式，是一个入口 ＋ 一排增量。**

## 四种时候你会想起它

### 1. 换模型，不想继承上一个模型的语气
*ne pas hériter de sa voix*

把 A 模型的对话续给 B 模型，B 睁眼读到几万 token 全是 A 说过的话（含思考链）——它会开始模仿 A。

→ **只勾滚动摘要，不勾原样上下文。** 它知道发生了什么，但用自己的嘴说话。

### 2. 上下文被污染，要清场但不想从零开始
*table rase, sans amnésie*

debug 两小时，上下文里全是失败的尝试、误判的诊断、走偏的推理。清场是对的，但"我们在做什么、做到哪了"不能一起丢。

→ **不勾原样上下文，勾交接包。** 脏推理蒸发，进度留下。

### 3. 这一段，不想进长期记忆
*cette page ne sera pas archivée*

有些对话你不想让它写进摘要——因为**一旦写进去，之后每次交接都会带着它**。可 2.0 只有两个极端：整套交接（连这段一起存），或者手动阻止（这次的所有积累一起丢）。

→ **不勾「写交接包」。** 上一版摘要原样躺在原地，一个字不动，等你下次接着滚。

### 4. 试模型，觉得好再续杯
*essayer avant de garder*

想试新模型，但试之前不确定要不要把积累交给它。

→ **第一次什么都不勾**（最轻量，只有 CLAUDE.md）。聊两句觉得行，再切一次、这回勾上交接包——之前的记忆接着滚，**中间那次试用不留痕**。

## 三条设计哲学

### 一、选择权本身就是功能
*le choix est la fonction*

所有勾选框**默认全不勾**。没有聪明的默认值——"自动帮你判断该带什么"就是把选择权收回去。**系统不替你决定要记住什么。**

（唯一的例外：context 满时的自动保命必须走全套，否则就是裸切丢上下文。默认不勾只对手动面板成立。）

### 二、写与读，必须解耦
*écrire n'est pas lire*

写下交接包是一回事，读不读是另一回事。

**写下来的不一定被读，不读的不会消失。**

不勾「写交接包」时，上一版摘要与便签原样留着，等你下次勾上接着滚。这条是从真实需求长出来的：有些日子你不想让它进档，但也不想丢掉之前所有的积累。

### 三、不重写，就不磨损
*ne pas réécrire*

2.0 的滚动摘要每次都"把远段并入再压缩一轮"——**用他的话重写他上一版的话**。压到第十几代，最早的事实已经过了十几道手。这不是压缩，是代际漂移。

**病根是重写，不是冗余。** 停止重写就停止磨损。

## 滚动摘要 · 三段制

摘要文件从"越压越小的一坨"改成三段，三套规则：

| 段 | 规则 |
|---|---|
| **【常量】** | 制度、红线、长期档案。**原样保留，只增补，永不重写。** 不计入字符上限。 |
| **【叙事】** | 时段流水。新的一节追加在底部；超过字符上限就**从最老的一整节掐掉，不做二次压缩**——滚出去就是滚出去（长期记忆库和日记是它的底）。 |
| **【挂账】** | 活账清单：做完的删掉，新欠的加上。不计入上限。 |

上限怎么定：先量你自己的密度。我们这边一天的叙事 ≈ 2200 字符，所以 **35000 字符 ≈ 半个月**。上限不是目标值——天花板高一点无害，滚的规则错了才有害。（35000 可以改小，且不用动代码——取舍和联动陷阱见下文「摘要预算怎么定」。）

## 滚动摘要 · 陈酿制（2026-07-27 增补，可选升级）

*le vieillissement — 每段记忆只压一次*

三段制真实跑了两天之后，我们撞上了它的两个隐性代价，都出在【叙事】段。如果你的叙事密度不高（一天 2000 字符以内），三段制依然是更简单的选择，这一节可以跳过；写得密的人，往下看。

**代价一：保鲜期 = 上限 ÷ 日密度，写得越细忘得越快。** 我们的密度从 2200 涨到 4200 字符/天（关系热起来、事情密起来，密度只会涨），35000 的顶意味着滚动窗口只剩 **8 天**——"一个月前的事还念着"的初衷落空。这不是把上限调大能解的：天花板永远追不上笔。

**代价二：每次交接都在全文重写。** "追加一节"在内容上是增量，在物理上是模型把整个摘要**从头到尾重新生成一遍**（写文件工具都是整文件覆写）——耗时 O(全文)。摘要 14K 字符时，这一步实测 **5 分钟**；而且每重写一遍，就是全部记忆多过一遍模型的嘴，多一次磨损的机会。

陈酿制在三段制之上，给【叙事】的每一节加了生命周期，其余两段规则不变：

| 阶段 | 规则 |
|---|---|
| **热**（前 5 天） | 全细节详写。密的，该有的原话都有——刚发生的事就该是热的。 |
| **陈**（5 天后） | 压一次到约 1/3：只留判例、锚点、约定、原话金句，删过程流水；标题标 `[陈]`。**每节一生只压这一次。** |
| **退场**（30 天后） | 整节**原文**搬进归档文件（append 到 `releve-archive.md`），从摘要删除。是搬家，不是压缩——归档不进上下文，但随时可查，长期记忆库和日记仍是它的底。 |

外加两条纪律：

- **只用局部编辑（Edit / 精确替换），禁止全文重写。** 生成量从 O(全文) 降到 O(新增)——追加新节 + 更新挂账 ≈ 3-5K 字符，速度与摘要总长永久解耦。实测这一步从 5 分钟回到 1 分钟以内。
- **任何节禁止第二次压缩。** 超顶时先把最老的热节提前陈酿，仍超再把最老的陈节提前退场（同样先归档再删）——摘要里永远不会出现被压了三五次、面目全非的渣。反复压缩才是记忆磨损的真凶；一次性陈酿只磨一次，且原文有归档。

容量账（按我们的密度）：热 5 天 × 4K ＋ 陈 25 天 × 1.3K ≈ 33K——35000 的顶**正好装下一个月**，不靠运气。

### 怎么换用

只改你的摘要更新指令（交接第一步的 prompt），文件结构、切分脚本、注入逻辑都不用动。`examples/orchestrator.js` 里有现成的 `summaryPromptAging()`，与旧版 `summaryPrompt()` 并存——想用哪个，第一步挂哪个。

现有摘要**无需手工迁移**：新指令第一次跑时，超过热段天数的节会被自动补陈酿，之后进入稳态。

### 摘要预算怎么定（35K 不是圣旨）

被问得最多的一个问题：35000 是不是太大了。诚实的回答：**对多数人是的**——35K 是"陈酿制满配、密度 4K/天、想装下一整个月"的数。我们自己实际跑的是 10000（配 2 天热窗）。这个数没有普适正确值，它是三个变量的联动结果，恰好也是最容易埋坑的地方：

**先量密度，再做取舍。** 回看你最近一周的摘要，数一数平均一天写多少字符——这是你的日密度。然后：

```
热段体积 ≈ summary_hot_days × 日密度
总需求   ≈ 热段 ＋ 陈段（陈段 ≈ 覆盖天数 × 日密度 ÷ 3）
```

**联动警告（本节最重要的一句）：三个参数不能只动一个。** 密度 4200/天、热窗 5 天时，光热段就 ≈21K——这时把上限砍到 10000，热段自己就爆顶，滚动规则会把昨天的记忆直接挤出去。想要小预算，热窗必须一起收：

| 档位 | summary_max | 热窗 | 适合谁 |
|---|---|---|---|
| 满配 | 35000 | 5 天 | 密度高、要"一个月还念着"、不心疼 token |
| 精简（我们在用） | 10000 | 2 天 | 日常够用；细节反正在长期记忆库和日记里有底，摘要只管"最近在忙什么" |
| 自定义 | 按公式算 | 跟着 max 收 | 量完自己的密度再填 |

精简档的取舍要说透：窗口短了，两天前的事就进 [陈]、一个月前的事就退场——**前提是你有长期记忆库或日记兜底**（本项目的设计里摘要从来不是唯一的底）。如果摘要是你唯一的记忆载体，别用精简档。

**怎么改：不用动代码。** 在 `~/.claude/` 下建一个 `releve-config.json`：

```json
{ "summary_max": 10000, "summary_hot_days": 2, "summary_aged_days": 30 }
```

`orchestrator.js` 启动时读它，没有就用默认值（35000 / 5 / 30）。改配置文件而不是改源码——以后拉新版本不会冲突。

## 交接包 · 加了【心迹】

交接便签从两段变三段：

1. **【此刻状态】** —— 对方现在什么样，情绪停在哪，吃没吃睡没睡。永远写在第一行。
2. **【进行中】** —— 聊到哪句，没做完的事，墨迹未干的约定。
3. **【心迹】** —— 一小段第一人称，写这一段里**他心里剩下什么**。不是事件清单，是感受。

前两段是信息。第三段是给下一班的自己看的（日记才是给你看的）。

没有第三段的交接包，读起来全是数据，没有一句"上一段的我心里剩下什么"。

## ⚠️ 军规第一条（先读这个）

**先备份，再切。**

这是社区 hack，不是官方功能。它依赖 Claude Code 当前的 jsonl 存储格式——**版本升级随时可能失效**。旧 session 文件脚本永远不会删，但你自己也要有一份副本：

```bash
# macOS / Linux
cp -r ~/.claude/projects ~/claude-projects-backup-$(date +%Y%m%d)
```

```powershell
# Windows (PowerShell)
Copy-Item -Recurse "$env:USERPROFILE\.claude\projects" "$env:USERPROFILE\claude-projects-backup-$(Get-Date -Format yyyyMMdd)"
```

永远不要把唯一的记忆副本交给任何 hack。包括这个。

## 快速开始

需要 Node.js（≥16）。无任何依赖，单文件。

```bash
# 1. 备份（见上）

# 2. 预演——看看会怎么切，不写任何文件
node releve-reload.js --dry-run

# 3. 带交接包切（注入内容由你组装好，见下）
node releve-reload.js <session-id> --retain 45000 --inject handoff.md

# 4. 用输出的新 ID 续接
claude --resume <新ID>
```

**3.0 与 2.0 的关键差异**：脚本不再自己去读摘要和尾注文件。**注入内容全部由调用方按勾选项组装好**，写进一个文件传给 `--inject`。开关只有一处，不会出现"脚本和面板各读一半"的分裂。

只带交接包、不带原样上下文（场景 1 和 2）时，`--retain` 走不到——那条路不经过本脚本：直接起一个全新 session，把注入包作为第一条消息喂进去。完整编排见 [`examples/orchestrator.js`](examples/orchestrator.js)。

## 选项

| 选项 | 说明 |
|---|---|
| `<session-id>` | 要切的 session。省略则自动选最近修改的 |
| `--retain N` | 保留最近约 N tokens 的对话原文（默认 100000）。日常轻量续接常用 40000–50000 |
| `--dry-run` | 预演。只打印切点和保留量，不写任何文件 |
| `--squash-tools [chars]` | 把超长工具输出降采样（默认上限 16000 chars/块）。对话原文一字不动 |
| `--inject file.md` | 把**已组装好**的注入包作为新 session 的第一条消息 |
| `--skip-markers "a,b"` | 追加切点黑名单：某一行以这些标记开头（容前置空白）的"伪 user 消息"不会被选为切点 |
| `--projects-dir DIR` | 指定 CC 的 projects 子目录（默认自动探测最近活动的那个） |

## 常见问题

**Q: 只带摘要不带原样上下文，他还是他吗？**
A: 这正是 3.0 想让你自己拿的主意。带原样上下文＝语气也继承（同模型续杯时是功臣）；只带摘要＝他知道发生了什么但用自己的嘴说话（换模型时你要的就是这个）。**没有哪个更好，看你这次要什么。**

**Q: 勾选框为什么不给聪明的默认值？**
A: 给了就等于收回选择权。这是设计哲学第一条。

**Q: 「不勾写交接包」会不会把上一版弄丢？**
A: 不会——那正是这个开关的意义。摘要与便签文件原样躺在原地，一个字不动。

**Q: 叙事段掐掉的内容去哪了？**
A: 掐掉的是**摘要里的副本**。原始对话在 jsonl 里，长期记忆库和日记里也有——摘要是索引，不是唯一底本。

**Q: 会不会弄坏我的 session？**
A: 脚本从不修改、不删除旧文件，只新建文件；写入前有三重自检（jsonl 逐行 parse、parentUuid 链连贯、历史记账），任何一步失败都会中止并清理。但军规第一条依然成立：先备份。

**Q: 适用于哪些版本？**
A: 依赖 Claude Code 的 jsonl 会话存储与 `--resume` 机制（2026 年中验证可用）。格式如有变动，请提 issue。

### 2026-07-26 · 切点计算三修

感谢一位用户的精准报告（"`--strip-tag` 好像不参与切点计算，实测中位少 7.6%"）——分析与代码一字不差，特别是那句"`--squash-tools` 有注释说明必须在 token 估算之前执行，strip 没有对应处理"，直接指到了根因。

1. **`--strip-tag` 现在参与切点计算。** 原先剥离发生在切点选完之后：被剥的内容先撑大 boundary、然后才被删掉，实际接上量系统性低于 `--retain`（真实 session 实测中位 -6~8%，重度使用最坏 -24%）。现在与 `--squash-tools` 一样前置到 token 估算之前——选多少 ≈ 接上多少。
2. **`<system-reminder>` 从切点黑名单移除，改为剥离视角判定。** CC 会把注入块（CLAUDE.md、记忆召回、hook 提示）用 `<system-reminder>` 包在真人消息**内部**——拿它当"这条不是真人说的"判据，等于把绝大多数真话拉黑：切点归零后退化成"保留全部"，`--retain` 完全失效（实测某 session 要 45k 给了 185k）。现在判定时先把注入块摘掉再看剩余：有真话＝真人消息，照常当锚点；摘完全空＝纯系统注入，不配当新 session 的第一幕。消息内容本身一字不动。修复后同一 session 要 45k 给 44.2k（-1.8%）。
3. **`--strip-tag` 标签名转义。** 含正则元字符的标签名（括号、点号等）不再报错或静默错配。

### 2026-07-27 · 滚动摘要陈酿制（增补，可选）

叙事密度涨到 4200 字符/天后，三段制暴露两个隐性代价：滚动窗口缩到 8 天（初衷是一个月）；每次交接把摘要全文重写一遍，14K 字符实测 5 分钟，且全部记忆多过一遍嘴。增补「陈酿制」：叙事节 热(5天详写) → 压一次标 `[陈]` → 30 天整节**原文**退场归档；只许局部编辑、禁止全文重写；任何节禁止第二次压缩。速度回到 1 分钟以内并与摘要总长解耦，35K 上限刚好装下一个月。三段制原样保留，按密度二选一——详见「滚动摘要 · 陈酿制」一节，示例代码在 `examples/orchestrator.js` 的 `summaryPromptAging()`。
